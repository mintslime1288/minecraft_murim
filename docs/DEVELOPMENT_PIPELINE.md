# 개발 파이프라인

1. `AGENTS.md`, 현재 코드, 관련 문서를 읽고 범위와 제외 항목을 확인한다.
2. 현재 브랜치와 `git status`, 최근 커밋, 원격 상태를 확인한다. 사용자 변경은 삭제하거나 되돌리지 않는다.
3. 도메인과 설정을 먼저 수정하고 Command·Listener에는 입력 변환만 둔다. 밸런스 값은 YAML에서 관리한다.
4. Paper 객체 없는 단위 테스트를 우선 작성하고 SQLite 재시작·호환 회귀 테스트를 추가한다.
5. Java 25에서 `./gradlew test`와 `./gradlew build`를 실행하고 전체 diff를 검토한다.
6. 서버 배포 전 `/stop`으로 완전히 종료하고 `plugins/MurimRPG/murimrpg.db`와 `realms.yml`을 백업한다. 기존 단계 구성이 바뀌면 이전 설정을 이름 변경해 보존하고 새 기본 설정을 생성한 뒤 사용자 밸런스를 수동 병합한다. 새 JAR 설치 후 완전 재시작한다.

기능 완료 보고에는 변경 파일, 테스트 결과, JAR 위치, 수동 테스트, 알려진 문제와 제외 범위를 포함한다.
