# 플레이어 Blockbench 애니메이션 템플릿

## 이어진 표면과 웨이트 관절 편집본 (2026-10-25)

`player_current_weighted_armature.bbmodel`은 Blockbench **자유 모델** 형식의
공개용 중립 스킨 편집본이다. 집 PC에서 현재 보이는 스킨을 입힌 로컬 편집본은
상위 작업 폴더의
`플레이어_Blockbench_수정용/현재_플레이어_연결관절_편집용_v3.bbmodel`이다.
Blockbench에서 이 로컬 파일을 열고 상단 **애니메이션** 탭에서 `+`를 눌러
클립을 만든 뒤 관절의 회전 키프레임을 넣으면 된다.

기본 체형은 현재 넓은 팔 플레이어와 같은 32픽셀 높이, 64×64 스킨 UV다.
몸통·머리는 한 메시이고 양쪽 팔·다리는 각각 독립된 메시다. 팔꿈치와
무릎을 포함한 각 팔다리 내부는 연속 표면을 유지한다. 겉옷·소매·바지·
모자 레이어는 각각 별도의 웨이트 메시다. 42개 뼈, 11개 메시,
총 396개 정점과 374개 면을 사용한다. 허벅지·정강이 및 상완·전완의
긴 부분은 큰 면과 단일 뼈 가중치를 사용하고, 무릎·팔꿈치의 앞뒤
2픽셀 주변에만 0.5픽셀 간격의 관절 단면과 가중치를 둔다. 허리·가슴·목,
어깨·손목·발목도 해당 위치 근처에서만 전환된다. 각 기본 메시가 한 연결
구성요소이고 모든 가장자리에 두 면이 붙어 있는 것을 검사했다.
팔꿈치·무릎에는 `In → 중앙 → Out` 뼈를 두고 부모·자식 연결을 켰다.
어깨·골반 안쪽에는 각 팔다리 뼈로 이어지는 Bridge 뼈를 추가했다.
Blockbench에서 `rightElbow`와 `rightKnee`를 각각 45도 굽힌 로컬 검사본
`현재_플레이어_연결관절_굽힘검사_v3.bbmodel`을 열어 확인했다.
다만 큰 회전에서는 텍스처가 늘어나거나 겉레이어가 겹칠
수 있으므로 실제 모션마다 살펴봐야 한다.

색깔이 있는 뼈 연결 구조는 Blockbench의 **편집용 armature 표시**다.
인게임에서 보이는 뼈 큐브가 아니다. `connected` 속성은 부모 뼈의
표시가 다음 자식 관절까지 이어지게 하며, 피부 변형은 각 정점의
`vertex_weights`가 담당한다. 기존 v2 파일과 그 안에서 사용자가
진행 중인 애니메이션은 덮어쓰지 않았다.

이 리그는 자유 모델의 armature/weight painting 기능을 쓰므로 위의 Bedrock
큐브 편집본과 형식이 다르다. **현재 Minecraft Java 모드의 PAL/Bendable
Cuboids 렌더러에 자동 적용되지는 않는다.** 애니메이션을 만든 후 `.bbmodel`
원본을 전달해야 게임용 표현 경로를 별도로 설계하고 적용할 수 있다.
걷기 이동 거리는 게임이 담당하므로 `root`에 평행 이동을 넣지 않는다.
검 공격은 `rightArm` 계열을 주로 쓰고 검집을 드는 `leftArm`은 따로 잡는다.

`build_weighted_armature_player.py`는 공개 중립 모델을 다시 생성하는 도구다.
`--input`에 64×64 와이드 스킨 Bedrock 편집본을, `--output`에 출력 경로를
줄 수 있다. 로컬 현재 스킨 원본과 출력본은 개인 개발 자산이므로 GitHub에
올리지 않는다. 기존 `player_animation_wide.bbmodel`과 이전 관절 편집본은
그대로 보존한다.

### 관절 조절

2026-10-25 교정: 첫 제작본은 자식 관절에 전체 모델 좌표를 그대로 넣어서
관절 조절점이 캐릭터 위로 떠 있었다. 현재 파일은 부모 관절 기준 좌표로
고쳐 다시 열어 확인했다. 이전에 Blockbench에서 저장한 상태는 로컬 작업
폴더의 `현재_플레이어_웨이트관절_사용자저장본_20261025.bbmodel`에 보존했다.

모션을 조절하려면 **편집** 탭에서 관절 위치를 옮기는 대신 **애니메이션**
탭에서 클립을 선택하거나 왼쪽 `+`로 만든다. 오른쪽 외곽선에서 예를 들어
`root > waist > rightLeg`를 펼쳐 관절을 고른 뒤, 타임라인의 **회전** 행 `+`를
눌러 키프레임을 넣고 왼쪽 X/Y/Z 각도를 바꾼다. 교정본에서 `rightLeg`의
X 회전을 30도로 설정했을 때 엉덩이에서 다리가 굽고 메시가 붙어 있는 것을
Blockbench 화면으로 확인했다. 이 자세는 동작 확인용이며 기본 모델에는
저장하지 않았다. 로컬 폴더의 `현재_플레이어_관절조절_예시.bbmodel`에서
해당 키프레임을 열어 조절 방식을 볼 수 있다.

### 팔다리 사이에 생기던 연결 면 수정

첫 웨이트 편집본은 몸통과 양팔·양다리를 한 표면으로 합쳐, 양다리가
벌어질 때 사타구니 사이에 면이 늘어나는 문제가 있었다. 현행 공개본과
위의 `연결관절_편집용_v3` 로컬본은 몸통·머리, 오른팔, 왼팔, 오른다리,
왼다리를 분리했다. 팔꿈치·무릎은 각각의 팔다리 메시 내부에서 이어진다.
양다리에 반대 방향 회전 키프레임을 넣은 로컬
`현재_플레이어_팔다리분리_동작검사.bbmodel`로 분리 상태를 확인한다.
이전 `팔다리분리_편집용`은 전체 표면을 1픽셀마다 나눠 관절 밖도 변형될
여지가 있었으므로 비교용으로 보존한다. 새 제작본은 긴 부분의 면을 합치고
관절 부근만 나눴다.
기존 `현재_플레이어_웨이트관절_편집용.bbmodel`은 사용자의 진행 중인
작업을 보호하기 위해 그대로 둔다. 새 모델은 게임 런타임에 자동 적용되지
않는다.

## 관절을 더 촘촘히 나눈 편집본 (2026-10-24)

`player_current_jointed_editable.bbmodel`은 현재 플레이어의 기본 크기와
64×64 UV를 유지한 **중립 스킨 공개본**이다. `build_jointed_player.py`가
기존 편집본을 바탕으로 생성한다. 개인 개발 스킨을 포함한 로컬 편집본은
상위 작업 폴더의 `플레이어_Blockbench_수정용/현재_플레이어_관절편집용.bbmodel`이다.
그 파일을 Blockbench에서 열어 모션을 만들면 된다. 원래의
`현재_플레이어_수정용.bbmodel`은 보존했다. 개인 스킨은 GitHub에 올리지 않는다.

리그는 32개 뼈와 75개 큐브다. 몸통은 골반→복부→가슴→어깨,
각 팔은 어깨→상완→팔꿈치→전완→손, 각 다리는 엉덩이→허벅지→무릎→정강이→발
순서로 이어진다. 목·머리와 손 아이템 기준 뼈도 있다. 팔꿈치·무릎 등의
안쪽 연결 큐브는 기본 자세에서 겉으로 보이지 않으며 적당히 굽힐 때
틈을 줄인다. 상위 뼈를 회전하면 하위 뼈도 함께 따라간다.

Blockbench의 **애니메이션** 탭에서 새 클립을 만들고, 뼈의 회전에
키프레임을 넣는다. 팔꿈치/무릎을 한 번에 크게 접기보다 상완/허벅지와
전완/정강이에 회전을 나눠 주면 표면의 벌어짐이 덜하다. 게임의 이동은
Minecraft가 처리하므로 `root`에 이동 키를 넣지 않는다. 작업 후 `.bbmodel`
원본과 내보낸 애니메이션을 함께 전달해야 Java 모드의 PAL/Bendable Cuboids
경로에 맞춰 적용할 수 있다. 저장만으로 게임에 반영되지 않는다.

이 모델은 큐브와 회전 뼈로 연결감을 높인 제작용 리그다. 큰 각도에서
사람 피부처럼 완전히 연속 변형되는 스킨 메시가 아니며, 관절 안쪽의
겹침이나 바깥쪽 벌어짐은 남을 수 있다. Blockbench에서 팔꿈치와 무릎을
각각 45도 굽힌 정적 자세를 열어 연결 큐브가 보이는 것을 확인했다.

## 지금 개발 게임에서 쓰는 기본 플레이어 편집본

`player_current_java_editable.bbmodel`은 현재 활성화된 Java 기본 플레이어
체형(넓은 팔)을 Blockbench에서 수정하기 위한 사본이다. 머리·몸통·좌우 팔·
좌우 다리와 현재 옵션에서 켜진 모자·재킷·소매·바지 겉레이어를 포함한다.
총 13개 큐브와 12개 뼈이며, 손 위치 검토용 `rightItem`·`leftItem` 뼈도 있다.
`current_player_uv.png`는 직접 그린 중립 편집 텍스처다.

집 PC 개발 계정 `Player716`의 기록된 UUID와 Minecraft 26.2의 기본 스킨
선택 규칙을 대조하면 넓은 팔 `Makena` 스킨이다. 이 컴퓨터에 설치된
Minecraft JAR에서 해당 PNG를 읽어 만든
`local/player_current_dev_skin.bbmodel`은 **로컬 전용**이다. 그 파일을
Blockbench에서 열면 현재 개발 게임의 기본 스킨 모습으로 직접 수정할 수
있다. Minecraft 원본 스킨 이미지를 포함하므로 GitHub에는 올리지 않는다.
사용자가 다른 계정이나 별도 스킨으로 게임에 접속하면 해당 계정의 64×64
스킨으로 교체해야 한다.

이 편집본은 게임에서 지금 사용하는 **바닐라 지오메트리의 사본**이다.
PAL과 Bendable Cuboids가 게임 실행 중 팔꿈치·무릎을 구부리는 변형까지
`.bbmodel` 하나에 저장된 것은 아니다. 파일을 수정해도 게임에 자동 반영되지
않으며, 수정한 `.bbmodel`을 전달받아 Java 렌더러/모션과 대조해 적용해야 한다.
게임 설정과 서버 데이터는 변경하지 않았다.

아래의 `player_animation_wide/slim.bbmodel`은 먼저 만든 일반 제작 템플릿으로
보존한다. 현재 게임 외형을 고치려면 위의 `player_current_dev_skin.bbmodel`을
사용한다.

사용자가 직접 플레이어 모션을 만들기 위한 편집 원본이다. Blockbench의
**File → New → Bedrock Player Model**에서 만든 기본 플레이어 모델을
`.bbmodel`로 저장했다. `player_animation_wide.bbmodel`은 4px 팔,
`player_animation_slim.bbmodel`은 3px 팔이다. 둘 다 64×64 스킨 UV,
32 모델 픽셀 높이, 기본 플레이어 머리·몸통·팔·다리 비율을 사용한다.
`rightItem`과 `leftItem`은 손 아이템 위치를 검토할 기준 뼈다.

Blockbench에서 해당 `.bbmodel`을 열고 상단 **애니메이션** 탭에서 왼쪽의
`+`로 클립을 추가한다. `root` 아래의 머리·몸통·좌우 팔·좌우 다리 뼈를
회전시키며 키프레임을 만든다. `root`의 이동으로 걷기 거리를 넣지 않는다.
게임의 실제 위치 이동은 Minecraft가 담당한다. 공격 모션에서는
`rightArm`을 주로 움직이고 검집을 든 `leftArm`이 검의 공격을 따라
휘둘리지 않는지 확인한다.

`neutral_player_uv.png`는 편집용으로 새로 그린 방향 구분 텍스처다.
완성된 게임 스킨이 아니며 두 `.bbmodel` 안에도 같은 텍스처가 포함된다.
원하면 Blockbench에서 본인 64×64 스킨으로 교체할 수 있다.

## 게임 적용과의 관계

현재 개발 게임은 Java Edition의 기본 플레이어 모델에 PAL 1.2.6과
Bendable Cuboids 모션을 적용한다. 이 Bedrock 형식 `.bbmodel`은 **제작
원본/시각 참조**이고, 저장하거나 Bedrock animation JSON으로 내보낸
것만으로 Java 모드에 자동 적용되지는 않는다. 완성한 `.bbmodel`을
전달하면 뼈 이름·축·회전 단위·시간을 현재 PAL 클립과 대조해 별도로
적용해야 한다. Blockbench의 기본 템플릿은 팔꿈치·무릎 연속 굽힘을
그대로 미리보기하지 못하므로, 그 구간은 게임의 Bendable Cuboids 확인이
필요하다. 기존 모션·게임 설정·서버 데이터는 이 템플릿으로 바뀌지 않는다.

Blockbench에서 와이드 파일을 다시 열어 중립 스킨과 애니메이션 탭을
확인했다. 슬림 파일은 같은 뼈 계층과 3px 팔 너비를 저장 구조로 검증했다.
