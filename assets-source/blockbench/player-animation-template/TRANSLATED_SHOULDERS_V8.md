# 걷기 어깨 위치 교차 v8

사용자가 요구한 것은 위에서 본 양쪽 어깨의 바깥 끝이 앞뒤로 엇갈리는
**위치 이동**이다. v7은 연결 관절의 회전으로 끝점 순서를 바꿨지만
팔 방향까지 같이 돌았다. v8은 v4에서 다시 시작하여 팔 자체의
회전과 상체 위치를 보존했다. v4~v7 파일은 그대로 남겼다.

| 시점 | 오른쪽 `ShoulderBridge` 위치 Z | 왼쪽 `ShoulderBridge` 위치 Z |
| --- | ---: | ---: |
| 0초 | +0.55 | −0.55 |
| 0.3초 | 0 | 0 |
| 0.6초 | −0.55 | +0.55 |
| 0.9초 | 0 | 0 |
| 1.2초 | +0.55 | −0.55 |

고정돼 있던 양쪽 어깨 연결 관절의 Y 회전 약 −10°는 0°로 맞췄다.
그대로 두면 양팔 시작점이 X=±5이므로 위에서 본 끝점 깊이가
약 ±0.87픽셀 치우쳐, 작은 위치 이동만으로는 서로 교차하지 않는다.
그 외 어깨 X/Z 회전, `rightArm`·`leftArm`의 모든 키, 몸통·골반·
무릎·발목·접지, 메시·스킨·UV·웨이트·본 계층은 보존했다.
새 위치 키는 0.05초 간격 25개이며 첫·끝 자세가 같다. 게임 코드,
서버, 이동 속도와 다른 행동의 모션은 변경하지 않았다.

구조 검사에서 공개·로컬 결과는 각각 v4 입력과 애니메이션 밖의
모든 필드가 같고, 대상 어깨 연결 관절 이외 애니메이터도 같다.
양팔 회전과 몸통 위치가 동일하며 공개·로컬 어깨 키가 일치한다.
Blockbench에서 현재 스킨본을 열어 **위 시점**의 0초와 0.6초를
비교했고 양 어깨의 앞뒤 순서가 바뀌는 것을 확인했다. 앞·뒤 시점에서는 이동하는 어깨
윗면이 몸통과 벌어지거나 겹치는지, 검·검집을 들었을 때 손 방향이
유지되는지 확인한다. 인게임 적용과 품질은 아직 검증하지 않았다.
